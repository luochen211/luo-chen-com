# 期货智能交易辅助系统：开发需求说明

版本：V1.0  
日期：2026 年 8 月 13 日

## 1. 文档目的

本文用于把客户想要的最终使用形态，转化为开发团队可以理解、拆分和验收的开发需求。

系统的主要形态是安装在客户电脑上的本地桌面终端。它负责本地数据、行情、策略信号展示、交易确认、风控和 CTP 执行；飞书负责资讯播报、语音指令入口和交易结果通知；讯联负责历史交易分析及策略优化结果展示。

本项目定位为“期货智能交易辅助与半自动执行系统”，不定义为无人值守的自动交易或严格意义上的高频交易系统。AI 可以生成建议和执行流程，但每笔实盘交易仍须由客户在确认界面完成最终确认。

## 2. 客户希望达到的结果

客户希望把过去两年多、分钟级的交易记录导入讯联，识别自己的交易习惯和策略模式，并结合实时行情、资讯和历史表现，获得可复盘、可调整的交易辅助。

最终使用时，客户应能完成以下闭环：

1. 早上指定时间收到关注品种的资讯，并通过飞书语音播报收听。
2. 交易时，本地电脑根据策略条件弹出交易建议，展示品种、方向、手数和价格。
3. 客户可以直接确认，也可以先修改价格；系统重新校验后，客户再次点击确认才下单。
4. 客户在外出时，可以通过飞书发送语音交易指令；本地电脑收到后仍弹窗等待人工确认。
5. 在期货公司和柜台权限允许的前提下，系统按账户上限拆分委托，并分别反馈已报、成交、部分成交、撤单或拒单状态。
6. 夜盘结束后生成夜盘总结，为次日日盘提供基于数据和历史规则的参考信息，并归档到本地。
7. 收盘后查看讯联的策略分析和优化建议，同时在本地查询交易、行情和重要资讯节点。

## 3. 推荐产品形态与系统边界

### 3.1 推荐形态：本地桌面端为核心，飞书为辅助入口

| 部分 | 主要职责 |
| --- | --- |
| 本地桌面终端 | 行情与 CTP 连接、交易弹窗、改价、人工确认、风控、多账户拆单、订单状态、本地缓存、夜盘报告 |
| 飞书 | 接收手机语音、推送文字/音频资讯、发送待确认指令通知、推送成交和夜盘报告 |
| 讯联平台 | 导入历史交易记录、识别交易策略、生成分析与优化建议；具体可否被本地系统读取，取决于其 API 能力 |
| 资讯平台 | 提供经授权的资讯 API 或其他稳定数据接口 |
| 期货公司/CTP | 提供行情、报单、撤单、资金、持仓和成交回报接口 |

### 3.2 重要边界

- 飞书服务器不能直接访问客户电脑的 `localhost`。手机语音到本地电脑之间需要安全消息网关、长连接或其他可达的中转方式。
- “有 API”不等于已经支持本项目所需的全部能力。讯联、资讯平台和期货公司都要分别确认接口范围、权限、频率和测试环境。
- 系统可以保证校验、提交报单和反馈状态，但不能保证市场一定成交，更不能预先承诺全部成交、成交速度或成交价格。
- 策略优化结果是历史样本或回测结果，属于参考建议；参数变更需要人工确认，并建议经过模拟盘或观察期验证。
- 本地缓存可以减少重复读取外部数据，但不能替代实时行情、交易柜台和资讯源的在线连接。

## 4. 功能需求

### M1. 历史交易导入与策略分析

#### 目标

让客户把过去两年多的分钟级交易记录清洗后导入讯联，并获得交易画像、历史表现和优化建议。

#### 功能

- 支持 CSV、Excel 等常见格式导入。
- 对时间、合约代码、开平仓方向、成交价格、成交手数、手续费和盈亏等字段进行映射、清洗和校验。
- 保留原始文件、清洗后的文件和导入日志，便于追溯。
- 按品种、交易方向、开平仓、时段和日期统计胜率、盈亏比、手续费、最大回撤等指标。
- 将清洗后的数据导入讯联，并记录导入批次和返回结果。
- 展示或链接到讯联生成的策略画像与优化建议。
- 如果讯联提供策略结果 API，则允许本地系统读取已确认的参数或建议；否则保留“讯联网页查看、人工确认后在本地配置”的工作方式。

#### 验收重点

- 一份真实历史文件可以完成字段映射、异常提示和可追溯导入。
- 导入前后记录数量、成交数量和金额能够核对。
- 报告明确区分历史统计、回测结果和未来参考建议。

### M2. 资讯采集、筛选、语音播报与本地归档

#### 目标

在客户设定的时间段内，采集关注品种和宏观主题的资讯，筛选后通过飞书推送，并保留本地可搜索的历史节点。

#### 功能

- 对接经授权的资讯 API；首期先支持一个明确、稳定的数据源。
- 配置关注品种、交易所代码、关键词、排除词和重要资讯级别。
- 对资讯去重、打标签、记录来源、发布时间和抓取时间。
- 默认在 07:00—09:00 之间生成晨报，具体时间可配置。
- 支持文字消息和音频/语音播报两种输出；语音能力以实际平台接口验证结果为准。
- 支持重大资讯即时推送，但需配置触发规则，避免普通资讯造成噪声。
- 将资讯全文或摘要、来源、时间、品种标签和关联行情写入本地缓存。

#### 验收重点

- 在配置时间内成功生成并推送关注品种资讯。
- 推送内容可追溯到原始来源和时间。
- 同一资讯重复抓取时不会重复播报。
- 资讯源不可用时有错误日志，不影响本地历史数据查询。

### M3. 本地交易建议、改价与人工确认

#### 目标

把策略信号或用户语音指令转化为一笔待确认交易，在本地电脑以清晰、可修改的弹窗呈现。

#### 标准交互

系统弹出“买入橡胶 4 手，推荐价 11,000”后：

1. 客户点击“改价”。
2. 推荐价字段解锁，客户输入 9,000。
3. 系统校验价格是否符合合约最小变动价位、涨跌停范围、可用资金和本地风控规则。
4. 弹窗更新保证金、账户分配和最终委托预览。
5. 客户点击“确认下单”，系统才向 CTP 提交委托。
6. 客户也可以点击“取消”，或等待超时自动取消。

#### 功能

- 置顶显示合约、方向、开平、手数、推荐价/委托价、资金、风控结果和有效期。
- 支持“确认下单”“改价”“取消”三个明确动作。
- 改价后必须重新校验，不能沿用旧的校验结果。
- 语音指令只能创建或修改待确认指令，不能绕过人工确认直接下单。
- 记录指令来源、原始文本、解析结果、修改前后价格、确认人、确认时间和最终报单结果。

### M4. 飞书语音指令与本地执行

#### 目标

客户在外出时，通过飞书发送类似“买橡胶 4 手，9,000 元”的语音或文字指令；本地电脑接收后弹窗，等待客户确认。

#### 功能链路

`飞书语音/文字 → 消息网关 → 本地客户端主动连接 → 指令解析 → 本地弹窗 → 人工确认 → CTP 报单 → 飞书反馈`

- 解析品种、合约、买卖方向、开平、手数和价格。
- 对无法确定的合约、方向、价格或数量标记为“需要补充”，不生成可下单指令。
- 交易电脑离线时，飞书返回“本地终端不可用”，不缓存成可自动执行订单。
- 对同一指令使用唯一 ID，避免重复推送或重复下单。
- 交易结果按账户和订单反馈已报、部分成交、全部成交、撤单、拒单、失败等状态。

### M5. 多账户拆单与风控

#### 目标

在账户权限、单账户委托上限和柜台能力允许的前提下，将一笔总量拆分到多个账户执行。

#### 功能

- 配置账户、账户上限、可用资金、品种权限和优先级。
- 根据客户确认的总手数生成拆单预览。
- 下单前检查单品种仓位、单账户委托上限、单日亏损限额、价格偏离、可用资金和最大委托量。
- 分别记录每个账户的报单、成交、撤单和失败原因。
- 任一账户失败时，按预先配置的策略暂停、继续或等待人工处理，不默认补单。
- 禁止把“已提交全部账户委托”展示为“全部成交”。

### M6. 夜盘总结与次日日盘提示

#### 目标

针对有夜盘的品种，在夜盘结束后生成总结，帮助客户在第二天日盘前了解夜盘变化。

#### 功能

- 按交易所、品种和交易日历配置夜盘时段，不把收盘时间写死在代码中。
- 汇总开盘价、收盘价、涨跌幅、成交量、持仓量、关键价位和异常波动。
- 关联夜盘期间采集的重要资讯及其发布时间。
- 生成文字报告，并按配置发送音频/语音播报。
- 支持夜盘结束后立即推送，或与次日晨报合并推送。
- 将报告、使用的数据范围、数据缺口和生成时间保存到本地。
- 结合客户已经确认的历史规则生成“次日日盘关注事项”，明确标注为参考建议。

#### 验收重点

- 不同品种按正确交易日归属夜盘数据。
- 节假日、无夜盘品种、行情缺失和服务中断时有明确状态。
- 报告可以回溯查询，并能看到数据来源和生成时间。

### M7. 本地数据缓存与复盘查询

- 使用 SQLite 作为首期本地结构化数据库；行情文件和大量原始数据可使用 Parquet 等文件格式。
- 本地保存历史交易、行情、资讯、策略参数、订单、成交、夜盘报告和操作审计日志。
- 支持按品种、日期、资讯关键词和订单状态查询。
- 重要资讯节点与对应时间段行情建立关联。
- 支持定期备份、恢复检查和数据库完整性检查。
- 断网时可以查询历史数据和已归档资讯，但不能假设断网时仍可实时交易或获取最新行情。

## 5. 推荐技术方案

| 层 | 推荐方案 | 说明 |
| --- | --- | --- |
| 本地桌面端 | Python + PySide6/PyQt | 快速开发弹窗、配置页、日志和本地查询；需验证 macOS/Windows 目标环境 |
| 交易接入 | CTP 官方接口或经过验证的封装 | 以期货公司提供的柜台、认证和测试环境为准 |
| 交易框架 | vn.py 可作为候选 | 先验证目标期货公司、柜台版本、多账户和夜盘交易时段支持情况 |
| 本地服务 | Python asyncio + WebSocket/HTTPS | 本地客户端主动连接消息网关，处理指令、心跳和断线重连 |
| 消息网关 | 飞书开放平台 + 轻量云端中转服务 | 只传递必要消息；交易执行仍在本地 |
| 数据库 | SQLite + 定期备份 | 首期足够；数据规模或并发明显增加时再评估 PostgreSQL |
| 资讯任务 | Python 定时任务/任务队列 | 需要重试、去重、限流和失败告警 |
| 语音 | 首选飞书已验证能力；必要时接入独立 ASR/TTS | 不把“免费”和“准确率”作为未验证承诺 |
| 测试 | pytest + 模拟 CTP/SimNow 环境 + 端到端回放 | 先模拟盘，再小规模实盘灰度 |

## 6. 开发阶段与工期

AI Coding 可以明显减少样板代码、页面、接口适配和测试脚本的编写时间，但不能替代外部权限申请、交易联调、异常测试和客户验收。以下是按“实际可验收结果”估算的工期，不是纯代码生成时间。

### 阶段一：本地模拟盘最小闭环（约 2—3 周）

- 本地桌面端基础框架。
- 模拟行情/模拟账户连接。
- 语音或文字指令解析。
- 交易弹窗、改价、重新校验、取消和人工确认。
- 模拟下单及状态回报。
- 基础日志和本地 SQLite。

### 阶段二：本地完整辅助系统（约 3—5 周）

- 真实行情接入验证。
- 风控、多账户拆单和订单状态管理。
- 历史数据导入与本地复盘。
- 资讯采集、筛选、晨报和夜盘总结。
- 本地备份、断线重连、异常恢复和可观测日志。

### 阶段三：飞书远程入口与平台联调（约 2—4 周）

- 飞书应用、事件权限和消息网关。
- 飞书语音/文字到本地待确认指令。
- 交易结果和报告回传。
- 讯联 API、资讯 API 和真实 CTP 参数联调。

### 阶段四：实盘灰度与验收（时间取决于外部条件）

- 期货公司权限、看穿式认证和多账户能力确认。
- 夜盘、节假日、断网、断电、柜台断线、部分成交和重复指令测试。
- 小额、少账户、少品种灰度。
- 客户按验收清单实际操作并确认问题关闭。

因此，可以把 AI Coding 后的预期表述为：2—3 周争取跑通本地模拟盘闭环，6—10 周完成主要功能和联调；实盘可用时间不能只按写代码时间承诺。

## 7. 首期建议范围

为了最快验证核心价值，首期建议只选两个品种、一个模拟账户和本地电脑端：

1. 导入一份真实历史交易记录并完成字段核对。
2. 本地保存交易和行情样本。
3. 做出一个本地交易弹窗，支持改价、校验、确认和取消。
4. 用模拟行情/模拟账户跑通报单状态回报。
5. 生成一个基础晨报和一个基础夜盘总结。
6. 在外部接口确认后，再接入讯联、资讯 API 和飞书远程指令。

首期不应把“全品种、多账户、实盘、全部成交、无人值守、讯联实时自动触发”作为同时交付条件。

## 8. 开发前必须拿到的资料

- 一份脱敏的历史交易文件，以及字段说明和期望分析结果。
- 讯联数据导入格式、API 文档、鉴权方式、策略结果读取能力和调用限制。
- 资讯平台 API 文档、授权范围、推送/抓取限制和历史数据能力。
- 飞书自建应用权限、事件回调、语音消息读取和音频发送能力。
- 期货公司 CTP 接入说明、BrokerID、AppID、测试环境、认证要求和多账户政策。
- 两个目标品种的交易所代码、交易时段、夜盘归属和交易日历。
- 单品种仓位上限、单账户最大委托量、单日亏损限额、最大价格偏离和超时规则。
- 客户电脑操作系统、联网方式、是否允许安装常驻客户端和备份位置。

## 9. 最终验收口径

项目验收应按以下顺序判断：

1. 能否在本地模拟环境稳定跑通“指令—弹窗—改价—人工确认—报单—状态回报”。
2. 能否正确处理取消、超时、部分成交、拒单、断线和重复指令。
3. 能否按交易日历生成晨报和夜盘总结，并完成本地归档。
4. 能否追溯每一条交易指令、每一次人工修改和每一笔账户回报。
5. 外部平台权限和真实接口完成后，再单独验收讯联、资讯和实盘多账户能力。

只有以上各阶段分别通过，才进入下一阶段；模拟盘通过不等于实盘可用，报单成功也不等于成交保证。
