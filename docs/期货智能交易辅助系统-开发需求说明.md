# 期货智能交易辅助系统：开发需求说明

版本：V1.0  
日期：2026 年 8 月 13 日

## 1. 文档目的

本文用于把客户想要的最终使用形态，转化为开发团队可以理解、拆分和验收的开发需求。

系统的主要产品是安装在客户电脑上的桌面软件。电脑软件负责盘口行情、策略信号展示、交易确认、改价、风控、账户拆单、CTP 执行和交易复盘；飞书负责资讯音频的接收与播放，也可作为外出时的语音指令入口；讯联负责历史交易分析及策略优化结果展示。电脑 App 不承担资讯音频播放主功能。

本项目定位为“期货智能交易辅助与半自动执行系统”，不定义为无人值守的自动交易或严格意义上的高频交易系统。AI 可以生成建议和执行流程，但每笔实盘交易仍须由客户在确认界面完成最终确认。

## 2. 客户希望达到的结果

客户希望把过去两年多、分钟级的交易记录导入讯联，识别自己的交易习惯和策略模式，并结合实时行情、资讯和历史表现，获得可复盘、可调整的交易辅助。

最终使用时，客户应能完成以下闭环：

1. 早上在飞书 App 收到关注品种的资讯音频并直接收听。
2. 交易时，在电脑 App 的盘口界面查看行情和五档报价。
3. 策略触发后，电脑 App 弹出“是否交易”确认框，展示品种、方向、手数和价格。
4. 客户可以选择“交易”、改价后交易，或选择“不交易”；任何选择都记录到复盘日志。
5. 在期货公司和柜台权限允许的前提下，系统按账户上限拆分委托，并分别反馈已报、成交、部分成交、撤单或拒单状态。
6. 收盘后在电脑 App 查看逐笔交易、策略表现、回撤和讯联优化建议。
7. 夜盘结束后生成夜盘总结，为次日日盘提供基于数据和历史规则的参考信息，并归档到本地。

## 3. 推荐产品形态与系统边界

### 3.1 产品定位：电脑桌面软件为主，飞书为可选辅助入口

本项目首先开发的是一个运行在客户电脑上的桌面软件，不是手机 App，也不是以飞书为主要操作界面的交易产品。

客户在电脑前时，可以完全通过桌面软件完成盘口查看、交易确认、改价、下单、成交跟踪、策略复盘和风控配置。资讯音频在飞书 App 中收听；飞书到电脑的语音交易指令属于外出时的扩展能力。

| 部分 | 主要职责 |
| --- | --- |
| 电脑桌面软件 | 盘口行情、策略信号、交易弹窗、改价、人工确认、风控、多账户拆单、订单状态、本地缓存和交易复盘；这是系统的核心交付物 |
| 飞书 | 接收和播放资讯音频；可选接收外出时的语音交易指令；不直接执行交易 |
| 讯联平台 | 导入历史交易记录、识别交易策略、生成分析与优化建议；具体可否被本地系统读取，取决于其 API 能力 |
| 资讯平台 | 提供经授权的资讯 API 或其他稳定数据接口 |
| 期货公司/CTP | 提供行情、报单、撤单、资金、持仓和成交回报接口 |

### 3.2 重要边界

- 飞书服务器不能直接访问客户电脑的 `localhost`。手机语音到本地电脑之间需要安全消息网关、长连接或其他可达的中转方式。
- “有 API”不等于已经支持本项目所需的全部能力。讯联、资讯平台和期货公司都要分别确认接口范围、权限、频率和测试环境。
- 系统可以保证校验、提交报单和反馈状态，但不能保证市场一定成交，更不能预先承诺全部成交、成交速度或成交价格。
- 策略优化结果是历史样本或回测结果，属于参考建议；参数变更需要人工确认，并建议经过模拟盘或观察期验证。
- 本地缓存可以减少重复读取外部数据，但不能替代实时行情、交易柜台和资讯源的在线连接。

## 4. 功能需求

### M1. 历史交易导入与策略分析

#### 目标

让客户把过去两年多的分钟级交易记录清洗后导入讯联，并获得交易画像、历史表现和优化建议。

#### 功能

- 支持 CSV、Excel 等常见格式导入。
- 对时间、合约代码、开平仓方向、成交价格、成交手数、手续费和盈亏等字段进行映射、清洗和校验。
- 保留原始文件、清洗后的文件和导入日志，便于追溯。
- 按品种、交易方向、开平仓、时段和日期统计胜率、盈亏比、手续费、最大回撤等指标。
- 将清洗后的数据导入讯联，并记录导入批次和返回结果。
- 展示或链接到讯联生成的策略画像与优化建议。
- 如果讯联提供策略结果 API，则允许本地系统读取已确认的参数或建议；否则保留“讯联网页查看、人工确认后在本地配置”的工作方式。

#### 验收重点

- 一份真实历史文件可以完成字段映射、异常提示和可追溯导入。
- 导入前后记录数量、成交数量和金额能够核对。
- 报告明确区分历史统计、回测结果和未来参考建议。

### M2. 资讯采集、筛选、飞书音频推送与本地归档

#### 目标

在客户设定的时间段内，采集关注品种和宏观主题的资讯，筛选后推送到飞书，由客户在飞书 App 中收听音频，并保留本地可搜索的历史节点。

#### 功能

- 对接经授权的资讯 API；首期先支持一个明确、稳定的数据源。
- 配置关注品种、交易所代码、关键词、排除词和重要资讯级别。
- 对资讯去重、打标签、记录来源、发布时间和抓取时间。
- 默认在 07:00—09:00 之间生成晨报，具体时间可配置。
- 支持向飞书推送文字消息和音频；音频在飞书 App 中播放，电脑交易软件不承担音频播放主流程。
- 支持重大资讯即时推送，但需配置触发规则，避免普通资讯造成噪声。
- 将资讯全文或摘要、来源、时间、品种标签和关联行情写入本地缓存。

#### 验收重点

- 在配置时间内成功生成并推送关注品种资讯。
- 推送内容可追溯到原始来源和时间。
- 同一资讯重复抓取时不会重复播报。
- 资讯源不可用时有错误日志，不影响本地历史数据查询。

### M3. 电脑端盘口、交易建议、改价与人工确认

#### 目标

把实时盘口和策略信号转化为一笔待确认交易，在电脑桌面软件的交易界面和弹窗中呈现，界面体验参考股票/期货交易软件。

#### 标准交互

系统弹出“买入橡胶 4 手，推荐价 11,000”后：

1. 客户点击“改价”。
2. 推荐价字段解锁，客户输入 9,000。
3. 系统校验价格是否符合合约最小变动价位、涨跌停范围、可用资金和本地风控规则。
4. 弹窗更新保证金、账户分配和最终委托预览。
5. 客户点击“确认下单”，系统才向 CTP 提交委托。
6. 客户也可以点击“取消”，或等待超时自动取消。

#### 功能

- 置顶显示合约、方向、开平、手数、推荐价/委托价、资金、风控结果和有效期。
- 支持“交易确认”“改价”“不交易”三个明确动作。
- 改价后必须重新校验，不能沿用旧的校验结果。
- 语音指令只能创建或修改待确认指令，不能绕过人工确认直接下单。
- 记录指令来源、原始文本、解析结果、修改前后价格、确认人、确认时间和最终报单结果。

### M4. 飞书语音指令与电脑软件执行（外出时可选扩展）

#### 目标

客户在外出时，可以通过飞书发送类似“买橡胶 4 手，9,000 元”的语音或文字指令；电脑上的桌面软件接收后弹窗，等待客户确认。客户在电脑前时，主要通过桌面软件的盘口和交易界面操作，不依赖飞书。

#### 功能链路

远程模式：`飞书语音/文字 → 消息网关 → 电脑桌面软件 → 指令解析 → 本地弹窗 → 人工确认 → CTP 报单 → 飞书反馈`

本地模式：`电脑桌面软件录入/接收指令 → 指令解析 → 本地弹窗 → 人工确认 → CTP 报单 → 桌面软件显示结果`

- 解析品种、合约、买卖方向、开平、手数和价格。
- 对无法确定的合约、方向、价格或数量标记为“需要补充”，不生成可下单指令。
- 交易电脑离线时，飞书返回“本地终端不可用”，不缓存成可自动执行订单。
- 对同一指令使用唯一 ID，避免重复推送或重复下单。
- 交易结果按账户和订单反馈已报、部分成交、全部成交、撤单、拒单、失败等状态。

### M5. 多账户拆单与风控

#### 目标

在账户权限、单账户委托上限和柜台能力允许的前提下，将一笔总量拆分到多个账户执行。

#### 功能

- 配置账户、账户上限、可用资金、品种权限和优先级。
- 根据客户确认的总手数生成拆单预览。
- 下单前检查单品种仓位、单账户委托上限、单日亏损限额、价格偏离、可用资金和最大委托量。
- 分别记录每个账户的报单、成交、撤单和失败原因。
- 任一账户失败时，按预先配置的策略暂停、继续或等待人工处理，不默认补单。
- 禁止把“已提交全部账户委托”展示为“全部成交”。

### M6. 夜盘总结与次日日盘提示

#### 目标

针对有夜盘的品种，在夜盘结束后生成总结，帮助客户在第二天日盘前了解夜盘变化。

#### 功能

- 按交易所、品种和交易日历配置夜盘时段，不把收盘时间写死在代码中。
- 汇总开盘价、收盘价、涨跌幅、成交量、持仓量、关键价位和异常波动。
- 关联夜盘期间采集的重要资讯及其发布时间。
- 生成文字报告，并按配置发送音频/语音播报。
- 支持夜盘结束后立即推送，或与次日晨报合并推送。
- 将报告、使用的数据范围、数据缺口和生成时间保存到本地。
- 结合客户已经确认的历史规则生成“次日日盘关注事项”，明确标注为参考建议。

#### 验收重点

- 不同品种按正确交易日归属夜盘数据。
- 节假日、无夜盘品种、行情缺失和服务中断时有明确状态。
- 报告可以回溯查询，并能看到数据来源和生成时间。

### M7. 本地数据缓存与复盘查询

- 使用 SQLite 作为首期本地结构化数据库；行情文件和大量原始数据可使用 Parquet 等文件格式。
- 本地保存历史交易、行情、资讯、策略参数、订单、成交、夜盘报告和操作审计日志。
- 支持按品种、日期、资讯关键词和订单状态查询。
- 重要资讯节点与对应时间段行情建立关联。
- 支持定期备份、恢复检查和数据库完整性检查。
- 断网时可以查询历史数据和已归档资讯，但不能假设断网时仍可实时交易或获取最新行情。

## 5. 推荐技术方案

| 层 | 推荐方案 | 说明 |
| --- | --- | --- |
| 电脑桌面软件 | Python + PySide6/PyQt | 本项目的核心交付物，负责弹窗、配置页、日志、本地查询和交易执行；需先确认 macOS/Windows 目标环境 |
| 交易接入 | CTP 官方接口或经过验证的封装 | 以期货公司提供的柜台、认证和测试环境为准 |
| 交易框架 | vn.py 可作为候选 | 先验证目标期货公司、柜台版本、多账户和夜盘交易时段支持情况 |
| 本地服务 | Python asyncio + WebSocket/HTTPS | 本地客户端主动连接消息网关，处理指令、心跳和断线重连 |
| 消息网关 | 飞书开放平台 + 轻量云端中转服务 | 只传递必要消息；交易执行仍在本地 |
| 数据库 | SQLite + 定期备份 | 首期足够；数据规模或并发明显增加时再评估 PostgreSQL |
| 资讯任务 | Python 定时任务/任务队列 | 需要重试、去重、限流和失败告警 |
| 语音 | 首选飞书已验证能力；必要时接入独立 ASR/TTS | 不把“免费”和“准确率”作为未验证承诺 |
| 测试 | pytest + 模拟 CTP/SimNow 环境 + 端到端回放 | 先模拟盘，再小规模实盘灰度 |

## 6. 开发阶段与工期

AI Coding 可以明显减少样板代码、页面、接口适配和测试脚本的编写时间，但不能替代外部权限申请、交易联调、异常测试和客户验收。以下是按“实际可验收结果”估算的工期，不是纯代码生成时间。

### 阶段一：本地模拟盘最小闭环（约 2—3 周）

- 本地桌面端基础框架。
- 模拟行情/模拟账户连接。
- 语音或文字指令解析。
- 交易弹窗、改价、重新校验、取消和人工确认。
- 模拟下单及状态回报。
- 基础日志和本地 SQLite。

### 阶段二：本地完整辅助系统（约 3—5 周）

- 真实行情接入验证。
- 风控、多账户拆单和订单状态管理。
- 历史数据导入与本地复盘。
- 资讯采集、筛选、晨报和夜盘总结。
- 本地备份、断线重连、异常恢复和可观测日志。

### 阶段三：飞书远程入口与平台联调（可选，约 2—4 周）

- 飞书应用、事件权限和消息网关。
- 飞书语音/文字到本地待确认指令。
- 交易结果和报告回传。
- 讯联 API、资讯 API 和真实 CTP 参数联调。

### 阶段四：实盘灰度与验收（时间取决于外部条件）

- 期货公司权限、看穿式认证和多账户能力确认。
- 夜盘、节假日、断网、断电、柜台断线、部分成交和重复指令测试。
- 小额、少账户、少品种灰度。
- 客户按验收清单实际操作并确认问题关闭。

因此，可以把 AI Coding 后的预期表述为：2—3 周争取跑通本地模拟盘闭环，6—10 周完成主要功能和联调；实盘可用时间不能只按写代码时间承诺。

## 7. 首期建议范围

为了最快验证核心价值，首期建议只选两个品种、一个模拟账户和电脑桌面软件：

1. 导入一份真实历史交易记录并完成字段核对。
2. 本地保存交易和行情样本。
3. 做出一个本地交易弹窗，支持改价、校验、确认和取消。
4. 用模拟行情/模拟账户跑通报单状态回报。
5. 生成一个基础晨报和一个基础夜盘总结。
6. 在外部接口确认后，再接入讯联、资讯 API；飞书远程指令作为桌面软件稳定后的可选扩展。

首期不应把“全品种、多账户、实盘、全部成交、无人值守、讯联实时自动触发”作为同时交付条件。

## 8. 开发前必须拿到的资料

- 一份脱敏的历史交易文件，以及字段说明和期望分析结果。
- 讯联数据导入格式、API 文档、鉴权方式、策略结果读取能力和调用限制。
- 资讯平台 API 文档、授权范围、推送/抓取限制和历史数据能力。
- 飞书自建应用权限、事件回调、语音消息读取和音频发送能力。
- 期货公司 CTP 接入说明、BrokerID、AppID、测试环境、认证要求和多账户政策。
- 两个目标品种的交易所代码、交易时段、夜盘归属和交易日历。
- 单品种仓位上限、单账户最大委托量、单日亏损限额、最大价格偏离和超时规则。
- 客户电脑操作系统、联网方式、是否允许安装常驻客户端和备份位置。

## 9. 最终验收口径

项目验收应按以下顺序判断：

1. 能否在本地模拟环境稳定跑通“指令—弹窗—改价—人工确认—报单—状态回报”。
2. 能否正确处理取消、超时、部分成交、拒单、断线和重复指令。
3. 能否按交易日历生成晨报和夜盘总结，并完成本地归档。
4. 能否追溯每一条交易指令、每一次人工修改和每一笔账户回报。
5. 外部平台权限和真实接口完成后，再单独验收讯联、资讯和实盘多账户能力。

只有以上各阶段分别通过，才进入下一阶段；模拟盘通过不等于实盘可用，报单成功也不等于成交保证。

## 10. 用户、设备和运行环境

### 10.1 主要用户

首期只考虑一个主要交易用户，不做复杂的组织化多用户权限系统。系统需要预留以下角色边界：

| 角色 | 权限 |
| --- | --- |
| 交易者 | 查看行情、接收策略信号、改价、选择交易/不交易、查看持仓和复盘 |
| 管理员 | 配置账户、品种、风控阈值、资讯关键词、备份和消息通道 |
| 开发/运维 | 查看技术日志、连接状态和错误信息；不能默认拥有实盘确认权限 |

### 10.2 首期设备要求

- 首要目标平台为 Windows 10/11 电脑。
- 软件作为常驻桌面程序运行，可最小化到系统托盘。
- 电脑需要保持开机、联网并连接期货公司柜台，才能接收实时行情和执行委托。
- 电脑休眠、关机、断网或桌面软件退出时，系统必须明确显示“不可接收交易指令”，不能静默等待。
- 飞书 App 运行在手机端，负责资讯音频播放；它不是桌面交易终端的替代品。
- 如果后续需要 macOS 或 iOS，只复用展示层和消息层，不假设 CTP 交易核心可以直接运行在 iOS。

## 11. 电脑 App 页面清单

### P1. 交易台

这是电脑 App 的首页和核心工作区，打开软件后默认进入。

页面区域：

1. 顶部连接状态：CTP、行情、飞书消息网关、最近同步时间。
2. 品种栏：当前合约、交易所、最新价、涨跌、成交量、持仓量、交易时段。
3. 行情区：分时、1 分钟、5 分钟、15 分钟和日线切换；支持缩放、拖动和十字光标。
4. 五档盘口：卖五到卖一、买一到买五、数量、最新价和买卖价差。
5. 策略信号区：策略名称、触发时间、触发条件、方向、建议手数、建议价格和信号有效期。
6. 下单确认区：交易、改价、不交易三个动作，明确显示“AI 给建议，人做决定”。
7. 持仓区：账户、合约、方向、数量、均价、最新价、浮动盈亏和保证金占用。
8. 运行日志：行情连接、策略触发、人工操作、报单和成交回报。

### P2. 交易复盘

页面目标是回答：“我今天做了什么、为什么做、执行得怎么样、结果如何”。

功能：

- 按交易日、品种、账户、方向和策略筛选。
- 显示当日交易次数、胜率、净盈亏、手续费、最大回撤和平均持仓时间。
- 逐笔列出委托时间、确认时间、报单时间、成交时间、合约、方向、数量、价格和结果。
- 点击单笔交易后，显示交易前后行情、五档盘口、策略信号、资讯关联和人工操作记录。
- 区分“策略建议”“人工修改”“人工确认”“实际成交”四个时间点。
- 支持导出 CSV/Excel；导出文件必须标注数据生成时间和筛选条件。

### P3. 策略分析

- 展示历史样本数量、胜率、盈亏比、最大回撤、手续费占比、品种分布、时段分布和连续盈亏。
- 展示讯联返回的策略画像和优化建议。
- 区分样本内回测、样本外验证、模拟盘结果和实盘结果。
- 优化建议只能进入“待观察参数”，不能直接写入实盘策略。
- 支持将一条建议加入模拟观察、标记为忽略或记录备注。

### P4. 账户与风控

- 账户列表：账户名称、期货公司、连接状态、可用资金、权益、保证金、持仓和权限。
- 品种配置：合约代码、交易所、最小变动价位、交易时段和夜盘归属。
- 风控配置：单笔最大手数、单品种最大仓位、单账户最大委托量、单日亏损限额、价格偏离阈值和信号超时。
- 风控配置修改需要记录修改前值、修改后值、操作者和时间。
- 风控检查失败时，只能显示失败原因和可采取动作，不能自动绕过。

## 12. 关键业务流程

### 12.1 软件启动流程

1. 启动桌面软件。
2. 加载本地配置和加密账户信息。
3. 检查本地数据库、配置版本和最近备份。
4. 连接行情接口、交易接口和消息网关。
5. 分别显示连接状态：已连接、连接中、失败、未配置。
6. 只有交易接口、行情接口和风控配置均处于可用状态，交易确认按钮才可用。
7. 如果仅能查看历史数据，首页必须显示“只读复盘模式”。

### 12.2 策略信号确认流程

1. 行情服务收到实时数据。
2. 本地策略规则判断是否触发信号。
3. 系统生成唯一 `signal_id`，记录品种、方向、开平、手数、推荐价格、触发规则和有效期。
4. 电脑 App 弹出置顶确认框，同时在运行日志中写入信号事件。
5. 用户可以选择：
   - “交易确认”：进入风控校验；
   - “改价”：解锁价格输入框；
   - “不交易”：关闭信号并记录拒绝原因，可选填备注。
6. 超过信号有效期后，按钮变为不可用，状态变为“已过期”。
7. 风控校验通过后，用户仍需再次点击最终交易确认。
8. 报单后显示已报、部分成交、全部成交、撤单、拒单或失败。

### 12.3 改价流程

1. 默认价格为策略推荐价，只读显示。
2. 用户点击“改价”。
3. 系统显示可编辑输入框，同时展示合约最小变动价位和允许价格范围。
4. 用户输入新价格。
5. 系统校验数字格式、最小变动价位、涨跌停范围、价格偏离和资金要求。
6. 校验失败时禁止最终确认，并说明具体原因。
7. 校验通过后更新预估保证金、拆单预览和最终委托价格。
8. 用户点击“锁定价格”后，价格恢复只读；用户再点击“交易确认”才可报单。
9. 修改前价格、修改后价格和修改时间必须写入审计日志。

### 12.4 手动下单流程

除策略信号外，交易者可以在交易台手动发起下单：

1. 选择合约。
2. 选择买/卖、开/平。
3. 输入数量和价格，或选择盘口价格。
4. 系统展示账户、保证金、风控检查和预估拆单结果。
5. 点击“生成交易确认框”。
6. 用户在确认框中选择交易或不交易。
7. 交易确认后才创建订单并发送至 CTP。

手动下单不能绕过策略、资金、价格、仓位和权限检查。

### 12.5 飞书资讯流程

1. 资讯任务按配置时间抓取关注品种和宏观关键词。
2. 系统去重、打标签、判断重要程度并写入本地资讯库。
3. 生成晨报或夜盘总结文本。
4. 生成音频文件或调用飞书可用的音频能力。
5. 将音频和文字摘要推送至客户飞书。
6. 客户在飞书 App 中播放；电脑 App 只显示“已生成、已发送、发送失败或待重试”。
7. 资讯正文、音频地址、推送时间和飞书消息 ID 写入本地归档。

### 12.6 交易复盘流程

1. 用户选择交易日期和品种。
2. 系统读取本地订单、成交、行情、策略信号和资讯节点。
3. 按时间轴合并为一条交易事件链。
4. 用户点击某笔交易，查看交易前后 5—15 分钟行情和盘口变化。
5. 用户可以添加复盘备注，例如“追高”“执行迟疑”“策略有效”“价格改得过远”。
6. 系统将备注和复盘标签保存到本地，不修改原始成交数据。

## 13. 订单和信号状态定义

### 13.1 信号状态

| 状态 | 含义 | 可操作动作 |
| --- | --- | --- |
| `SIGNAL_CREATED` | 本地策略已生成信号 | 交易、改价、不交易 |
| `WAITING_CONFIRM` | 等待人工确认 | 交易、改价、不交易 |
| `PRICE_EDITING` | 用户正在改价 | 修改、锁定、取消 |
| `RISK_REJECTED` | 风控未通过 | 查看原因、关闭 |
| `EXPIRED` | 超过有效期 | 不可下单 |
| `DECLINED` | 用户选择不交易 | 查看记录 |
| `CONFIRMED` | 用户已确认交易 | 等待报单结果 |

### 13.2 委托状态

| 状态 | 含义 |
| --- | --- |
| `PENDING_SUBMIT` | 等待提交 |
| `SUBMITTED` | 已向 CTP 提交 |
| `PARTIAL_FILLED` | 部分成交 |
| `FILLED` | 全部成交 |
| `CANCEL_PENDING` | 等待撤单结果 |
| `CANCELLED` | 已撤单 |
| `REJECTED` | 柜台或风控拒单 |
| `CONNECTION_FAILED` | 连接失败，未确认是否报单成功 |

`CONNECTION_FAILED` 不能直接转换为“未成交”。系统必须提供订单查询和人工核对入口，防止网络异常造成重复下单。

### 14.1 交易信号表 `signals`

| 字段 | 说明 |
| --- | --- |

| `created_at` | 信号生成时间 |
| `symbol` | 合约代码 |

| 字段 | 说明 |
| --- | --- |
| `confirmation_id` | 确认记录 ID |
| `signal_id` | 关联信号 |
| `action` | 交易、改价、不交易 |
| `original_price` | 原推荐价 |

保存交易 ID、标签、备注、关联行情时间窗、创建时间和修改时间。复盘备注只作为用户分析资料，不覆盖柜台原始数据。

## 15. 内部接口约定

### 15.1 行情事件

```json
{
  "type": "market_tick",
  "symbol": "RU_MAIN",
  "last_price": 16980,
  "bid1": 16980,
  "ask1": 16990,
  "volume": 128400,
  "open_interest": 312800,
  "timestamp": "2026-08-14T09:38:24+08:00"
}
```

### 15.2 创建确认单

```json
{
  "signal_id": "sig_20260814_093742_001",
  "symbol": "RU_MAIN",
  "side": "BUY",
  "offset": "OPEN",
  "quantity": 100,
  "price": 16900,
  "source": "LOCAL_STRATEGY",
  "expires_at": "2026-08-14T09:39:00+08:00"
}
```

### 15.3 确认结果

```json
{
  "signal_id": "sig_20260814_093742_001",
  "action": "CONFIRM",
  "original_price": 16900,
  "final_price": 16920,
  "operator": "trader",
  "confirmed_at": "2026-08-14T09:38:41+08:00"
}
```

接口要求：

- 所有交易请求必须带唯一 ID，支持幂等处理。
- 所有时间统一保存为带时区的 ISO 8601 时间或明确的本地时间字段。
- 交易接口返回原始错误码和用户可读错误说明。
- 消息网关断线时，本地交易台仍可进入只读或本地手动模式，但不能假设飞书指令已送达。

## 16. 非功能需求

### 16.1 性能

- 本地桌面软件打开交易确认框目标小于 500ms，不把网络语音链路计入本地弹窗耗时。
- 盘口刷新应支持至少 1 秒级更新；真实频率以期货公司接口和账户权限为准。
- 本地查询两年交易记录的常用筛选目标小于 2 秒。
- 复盘页面加载单日交易记录目标小于 3 秒。
- 交易软件不能因为资讯抓取或复盘计算阻塞交易界面。

### 16.2 稳定性

- CTP 断线后显示断线时间，按退避策略重连，并区分行情连接和交易连接。
- 程序崩溃后重启，不能重复提交上一次订单。
- 本地数据库写入失败时，禁止继续假装已记录审计日志。
- 每次启动检查最近备份是否可恢复，备份失败需要明显提示。

### 16.3 安全

- CTP 密码、AppID 和授权信息不能写入源码、日志或普通明文配置。
- 本地敏感配置使用系统凭据管理或加密文件保存。
- 飞书只接收必要的资讯、指令状态和成交摘要，不发送完整账户密码和本地数据库。
- 远程语音指令必须绑定飞书用户、设备或授权范围。
- 交易确认、改价、不交易、风控修改和账户配置都要写入不可静默删除的审计日志。

## 17. 异常和边界场景

- 价格输入不是最小变动价位的整数倍：禁止确认并提示修正。
- 价格超出涨跌停范围：禁止确认并显示交易所/柜台返回范围。
- 可用资金不足：显示需要资金和当前可用资金，不自动减少手数。
- 单账户超过委托上限：显示拆单预览；若没有可用账户，禁止下单。
- 行情停止更新：信号自动失效，交易按钮进入不可用状态。
- CTP 报单超时：显示“待查询”，不自动重报。
- 部分成交：显示已成交数量、剩余数量和撤单入口。
- 夜盘跨自然日：使用交易日历归属，不按自然日期简单切分。
- 飞书音频生成失败：保留文字晨报，显示音频生成失败并支持重试。
- 资讯源重复或时间异常：保留原始来源，标记异常，不重复播报。
- 讯联 API 不可用：保留最近一次分析结果并标注时间，不伪造最新建议。

## 19. 本次开发明确不做的内容

- 不做无人确认自动下单。
- 不保证全部成交、成交价格或固定延迟。
- 不把飞书做成完整的期货交易软件。
- 不在电脑 App 内复制一套资讯音频播放器作为主流程。
- 不把讯联的历史回测结果直接当成实盘信号。
- 不在没有期货公司授权的情况下承诺多账户实盘拆单。
- 不在首期同时支持所有品种、所有交易所和所有柜台。
- 不把 iOS App 作为第一期交易执行端。
