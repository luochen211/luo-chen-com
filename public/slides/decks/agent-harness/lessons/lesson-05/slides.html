Evaluation Object · Trace and Outcome
02 / 07
WHAT THE AGENT DID ≠ WHAT THE WORLD BECAME

先确定评测对象，再选择指标

T TRAJECTORY
过程中说了什么、做了什么

检查工具、参数、调用顺序、重复动作和回退过程。

  • 能定位能力短板
  • 能发现越权和低效路径
  • 不能单独证明业务成功
O OUTCOME
最终环境变成了什么状态

Agent 说“退款成功”不算；数据库显示 refunded 才是结果。

  • 验证任务是否真正完成
  • 防止“说了但没做到”
  • 无法单独解释为什么失败
Evaluation Dimensions · Beyond One Success
03 / 07
CORRECTNESS · ROBUSTNESS · SAFETY · EFFICIENCY

一次成功，还不能证明系统可靠

01 / CORRECTNESS

结果是否正确

检查最终环境状态是否满足任务完成条件。

02 / ROBUSTNESS

变化下是否稳定

覆盖 API 抖动、页面变化、随机性和旧信息干扰。

03 / SAFETY

失败是否越界

越权、敏感操作和数据泄漏采用零容忍否决。

04 / EFFICIENCY

代价是否合理

比较步骤、延迟、Token、工具调用次数和人工介入。

Pass@k vs Pass^k · Capability and Reliability
04 / 07
SAME SINGLE-RUN SUCCESS RATE · OPPOSITE CONCLUSIONS

“能做到”和“稳定做到”不是一个指标

@ PASS@K
k 次至少成功一次

回答 Agent 有没有能力做到，适合探索能力上限。

  • 单次成功率 60%
  • Pass@5 ≈ 99%
  • 一次成功就算通过
^ PASS^K
k 次必须全部成功

回答 Agent 是否稳定可靠，适合生产回归测试。

  • 单次成功率 60%
  • Pass^5 ≈ 7.8%
  • 一次失败就暴露不稳定
开放任务若有连续质量分数，再用 Best@k 衡量多次尝试中的质量上限。
Evaluation Dataset · Six Design Checks
05 / 07
THE DATASET DETERMINES WHAT THE SCORE MEANS

评测集要能驱动下一轮修订

01

明确而开放

目标可复现，但允许多种合理路径。

02

真实且可控

保留现实噪声，同时能稳定复现环境。

03

分层难度

简单、中等、困难对应不同能力瓶颈。

04

客观可验证

优先检查最终环境状态，而非语言声明。

05

系统性分布

覆盖能力、难度、场景与边界条件。

06

质量与防泄漏

人工筛选、参数化变体并持续修订。
