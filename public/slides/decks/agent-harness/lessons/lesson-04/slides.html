Single vs Multi Agent · Split Criteria
06 / 09
THE KEY QUESTION IS INFORMATION GAIN

多 Agent 不是默认升级

1 SINGLE AGENT + SKILLS
没有新信息

如果只是让多个角色重看同一段材料，单 Agent 增加计算通常也能做到。

  • 协作不产生额外证据
  • 通信增加成本
  • 不应为了角色名而拆分
N MULTI AGENT
引入新信息

Reviewer 能获得测试结果、渲染截图或外部工具验证时，协作才有实质增益。

  • 共享或隔离上下文都可设计
  • 交接传结构化摘要
  • 评测必须覆盖协作轨迹

08 / 09
SHARE CONCLUSIONS + EVIDENCE POINTERS, NOT THE ENTIRE TRAJECTORY

Agent 之间交接的是任务包，不是整段聊天

01 HANDOFF PACKAGE
最小充分上下文

让接手者知道要完成什么、已经确认什么，以及去哪里读取证据。

  • 任务目标与验收标准
  • 已确认事实与关键约束
  • 产物、测试和截图的引用
02 DO NOT COPY
无差别复制完整轨迹

原始历史会挤占 Context，还会让接手者重新判断已经完成的工作。

  • 噪声与重复信息过多
  • 责任边界和完成状态模糊
  • 需要时再按引用回读原始证据
