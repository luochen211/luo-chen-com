RUN HISTORY IS NOT LONG-TERM MEMORY

流水账和用户档案，不是一回事

T TRAJECTORY
一次运行的证据账本

服务当前任务决策与事后复盘，保留事件发生的原始顺序。

  • 只属于这一次运行
  • 追加新事实，不覆盖旧历史
  • 任务结束后通常归档
M USER MEMORY
面向未来的用户预测模型

只提炼会影响未来判断的稳定特征，不追求保存完整对话。

  • 跨多次任务持续使用
  • 允许改写、合并与淘汰
  • 与特定用户身份绑定

Progressive Disclosure · Context Delta
31 / 37
THE CHANGE HAPPENS INSIDE CONTEXT

加载 Skill 前后，模型看见了什么变化？

01 BEFORE LOAD
Context 只有能力索引

模型知道存在“部署应用”这项能力，但完整流程尚未占用上下文。

  • 当前目标与任务状态
  • Skill 名称和一句话摘要
  • 没有部署步骤和执行器细节
02 AFTER LOAD
只注入本次需要的细节

匹配任务后，Harness 才把部署方法、执行接口和验收条件编入 Context。

  • 部署顺序、规则与失败处理
  • Bash Tool 的参数和返回格式
  • 构建、发布与验证的完成标准
渐进式披露不是隐藏能力，而是让每次模型调用只承担当前任务需要的认知负担。

Agent Handoff · Minimal Sufficient Package
33 / 37
SHARE CONCLUSIONS + EVIDENCE POINTERS, NOT THE ENTIRE TRAJECTORY

Agent 之间交接的是任务包，不是整段聊天

01 HANDOFF PACKAGE
最小充分上下文

让接手者知道要完成什么、已经确认什么，以及去哪里读取证据。

  • 任务目标与验收标准
  • 已确认事实与关键约束
  • 产物、测试和截图的引用
02 DO NOT COPY
无差别复制完整轨迹

原始历史会挤占 Context，还会让接手者重新判断已经完成的工作。

  • 噪声与重复信息过多
  • 责任边界和完成状态模糊
  • 需要时再按引用回读原始证据
Evaluation Dimensions · Beyond One Success
34 / 37
CORRECTNESS · ROBUSTNESS · SAFETY · EFFICIENCY

一次成功，还不能证明系统可靠

01 / CORRECTNESS

结果是否正确

检查最终环境状态是否满足任务完成条件。

02 / ROBUSTNESS

变化下是否稳定

覆盖 API 抖动、页面变化、随机性和旧信息干扰。

03 / SAFETY

失败是否越界

越权、敏感操作和数据泄漏采用零容忍否决。

04 / EFFICIENCY

代价是否合理

比较步骤、延迟、Token、工具调用次数和人工介入。

06

质量与防泄漏

人工筛选、参数化变体并持续修订。
