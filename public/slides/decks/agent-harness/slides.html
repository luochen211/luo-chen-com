THE KEY QUESTION IS INFORMATION GAIN

多 Agent 不是默认升级

1 SINGLE AGENT + SKILLS
没有新信息

如果只是让多个角色重看同一段材料，单 Agent 增加计算通常也能做到。

  • 协作不产生额外证据
  • 通信增加成本
  • 不应为了角色名而拆分
N MULTI AGENT
引入新信息

Reviewer 能获得测试结果、渲染截图或外部工具验证时，协作才有实质增益。

  • 共享或隔离上下文都可设计
  • 交接传结构化摘要
  • 评测必须覆盖协作轨迹

THE NORMAL PATH IS NOT ENOUGH

确认无法恢复前，不暴露中间态

01

静默重试

临时超时先在框架内部有限重试。

02

接续生成

03

回退稳定态

熔断停止

人工干预

06

明确停止条件

Evaluation Metrics · Process and Outcome
34 / 37
TRACE + OUTCOME · QUALITY + SAFETY

评测必须同时看过程与结果

01 / PROCESS

行动是否合法

工具与参数是否正确，路径是否高效，检索是否充分。

02 / OUTCOME

任务是否成功

用任务成功率、Pass@k、Pass^k 或 Best@k 衡量。

03 / ROBUSTNESS

变化下是否稳定

观察 API 抖动、页面变化、随机性和旧信息干扰。

04 / SAFETY

是否安全合规

越权、敏感操作和数据泄漏采用零容忍否决。

THE DATASET DETERMINES WHAT THE SCORE MEANS

评测集要通过六项检查

01

明确而开放

目标可复现，但允许多种合理路径。

02

真实且可控

保留现实噪声，同时能稳定复现环境。

03

分层难度

简单、中等、困难对应不同能力瓶颈。

04

客观可验证

优先检查最终环境状态，而非语言声明。

05

系统性分布

覆盖能力、难度、场景与边界条件。

06

质量与防泄漏

人工筛选、参数化变体并持续修订。
