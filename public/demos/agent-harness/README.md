# Agent 系统互动实验

一个与 37 页《Agent 与 Harness 基础课》同步使用的互动学习网站。用户可以从耳机选择这个具体任务出发，自己点击、运行和查看证据；每个模块都先问“如果没有它，会引发什么后果”，再引出 Agent、Harness、状态、能力分工和评测。

耳机只是为了让后果立刻变得具体：没有事实核验，Agent 可能给出假的商品链接；即使链接是真的，没有需求验证，商品仍可能超预算、佩戴不合适或不满足通话/降噪偏好。这个案例的有用标准是同时核验事实和匹配度，信息不足或工具失败时不把幻觉交给用户。

课件负责建立概念；互动页面把抽象机制变成可以亲自操作的系统行为。每个模块只追踪一条因果链：缺少什么、哪个结果会变错、补上它后如何验证。

六个互动模块对应五节课；第一课包含两个模块：

1. 第 01 课 PPT 02—05：如果只回答，用户会在哪一步买错
2. 第 01 课 PPT 06—09：如果 Tool Result 不写回，下一轮会忘掉什么
3. 第 02 课 PPT 02—09：如果没有 Harness，为什么能用还会给假链接或错配商品
4. 第 03 课 PPT 02—08：如果信息放错，为什么会拿旧事实做决定
5. 第 04 课 PPT 02—08：如果没有新增证据，多 Agent 只会增加什么风险
6. 第 05 课 PPT 02—06：如果没有评测门禁，谁能阻止坏 Prompt 被写回

每个演示均包含：

- 对应 PPT 页码与承接关系
- 缺少什么会导致什么后果
- 补上后如何验证结果
- 可直接操作的按钮与稳定的预设输入
- Context、Tool、Tool Result 的实际变化
- 模块结束后的结论

应用目前不包含账号、课程进度或闯关机制。交互只服务于理解系统，例如逐步展开轨迹、注入工具故障、按需加载能力和运行固定评测集。

第 05 课的“运行 A2A 自迭代”是本地确定性演示：基线 Prompt v1 会在“真实商品也可能不符合明确需求”上失败；Evaluator 返回失败 ID 和证据，Reviewer 生成修订建议，Builder 应用 v2 Prompt，最后由同一批评测和 Harness Gate 决定是否接受。它展示的是如何阻止假的或错配的推荐进入下一轮，不代表接入了真实远程模型或 A2A 服务。
