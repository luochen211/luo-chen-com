# Agent 系统互动实验

一个与 37 页《Agent 与 Harness 基础课》同步使用的互动学习网站。用户可以从耳机选择这个具体任务出发，自己点击、运行和查看证据，逐步理解 Agent 为什么存在，以及为什么还需要 Harness、状态、能力分工和评测。

耳机只是为了让任务立刻变得具体：买错会浪费钱，预算、佩戴禁忌和通话/降噪偏好都会改变选择。这个案例的有用标准不是“推荐了几款”，而是降低买错概率：不超预算、不违反明确禁忌、理由能回指商品数据，信息不足或工具失败时不乱给结论。

课件负责建立概念；互动页面把抽象机制变成可以亲自操作的系统行为。每个模块只解决一个问题，并明确展示这次操作验证了什么、哪些证据发生了变化、最后得到什么结论。

六个互动模块对应五节课；第一课包含两个模块：

1. 第 01 课 PPT 02—05：判断“一次回答”和“完成任务”的边界
2. 第 01 课 PPT 06—09：逐步查看 LLM、Context、Tools 与 ReAct 轨迹
3. 第 02 课 PPT 02—09：对比没有 Harness 和存在故障恢复时的结果
4. 第 03 课 PPT 02—08：分类 Trajectory、State、Context、Memory、RAG 与实时 Tool
5. 第 04 课 PPT 02—08：查看 Skill、Tool 的按需发现，以及 Reviewer 如何通过外部验证获得新信息
6. 第 05 课 PPT 02—06：让固定评测集驱动 Builder、Evaluator、Reviewer 的 A2A 交接与 Prompt 回归

每个演示均包含：

- 对应 PPT 页码与承接关系
- 本模块需要理解的必要概念
- 本次互动验证的唯一结论
- 可直接操作的按钮与稳定的预设输入
- 操作后应该看到的三个变化
- 模块结束后的结论

应用目前不包含账号、课程进度或闯关机制。交互只服务于理解系统，例如逐步展开轨迹、注入工具故障、按需加载能力和运行固定评测集。

第 05 课的“运行 A2A 自迭代”是本地确定性演示：基线 Prompt v1 会在“否定偏好不丢失”上失败；Evaluator 返回失败 ID 和证据，Reviewer 生成修订建议，Builder 应用 v2 Prompt，最后由同一批评测和 Harness Gate 决定是否接受。它展示的是“如何减少买错”这一可理解的业务目标如何约束 Prompt 和代码，不代表接入了真实远程模型或 A2A 服务。
