# Agent Harness 讲师演示台

一个与 37 页《Agent 与 Harness 基础课》同步使用的课堂演示应用。它由讲师操作，不是发给学员自行闯关的学习产品。

耳机只是为了让观众立刻理解任务：买错会浪费钱，预算、佩戴禁忌和通话/降噪偏好都会改变选择。这个案例的有用标准不是“推荐了几款”，而是降低买错概率：不超预算、不违反明确禁忌、理由能回指商品数据，信息不足或工具失败时不乱给结论。

PPT 负责建立概念；演示台只在关键节点把抽象机制变成现场可见的系统行为。每个演示严格围绕一个证明目标展开，并明确提示讲师应该让观众观察什么、最后落到哪一句结论。

六个讲师实验对应五节 PPT；第一课包含两个实验：

1. 第 01 课 PPT 02—05：判断“一次回答”和“完成任务”的边界
2. 第 01 课 PPT 06—09：逐步观察 LLM、Context、Tools 与 ReAct 轨迹
3. 第 02 课 PPT 02—09：对比没有 Harness 和存在故障恢复时的结果
4. 第 03 课 PPT 02—08：分类 Trajectory、State、Context、Memory、RAG 与实时 Tool
5. 第 04 课 PPT 02—08：观察 Skill、Tool 的按需发现，以及 Reviewer 如何通过外部验证获得新信息
6. 第 05 课 PPT 02—06：让固定评测集驱动 Builder、Evaluator、Reviewer 的 A2A 交接与 Prompt 回归

每个演示均包含：

- 对应 PPT 页码与承接关系
- 讲师只需讲清的必要概念
- 本次演示唯一要证明的结论
- 讲师控制按钮与稳定的预设输入
- 三个需要引导观众观察的变化
- 演示结束后的一句话落点

应用不包含学员账号、课程进度、闯关或答题机制。保留的交互只服务于讲师控制演示节奏，例如逐步展开轨迹、注入工具故障、按需加载能力和运行固定评测集。

第 05 课的“运行 A2A 自迭代”是本地确定性演示：基线 Prompt v1 会在“否定偏好不丢失”上失败；Evaluator 返回失败 ID 和证据，Reviewer 生成修订建议，Builder 应用 v2 Prompt，最后由同一批评测和 Harness Gate 决定是否接受。它展示的是“如何减少买错”这一可理解的业务目标如何约束 Prompt 和代码，不代表接入了真实远程模型或 A2A 服务。
